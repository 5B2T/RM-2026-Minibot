# 主控侧接入说明：电位器 → 机械臂目标角

> **2026-10-25 本地接入进度与修正（优先于下文旧示例）**
>
> 当前只完成远端合并、V3扩展校验及只读遥测显示，尚未实现 `Arm_FollowTargets()` 或基座位置环，不代表电位器已能控制机械臂；本轮未烧录。原版未更新的主控会拒收带0x04的帧，不能理解为仅忽略新增字段。
>
> - V3目标角单位为 **0.1°**；独立V4遥测单位为 **0.01°**。遥测允许POT_MODE与333°上限。目标标志仅允许V3普通控制帧使用，要求掩码0x1F、模式1、末字节0；STOP/RESUME不得携带目标扩展。
> - 后续跟随必须使用本地结构限位：J1 10～150°、J2 23～180°、J3 13～270°、J4 0～180°；J5夹爪0～30°仍走按键。`Servos[].MaxAngleDeg`是电气换算量程，不能代替结构限位。电位器默认映射仍待现场标定，333°不代表底座机械行程。
> - “有新目标样本”与“目标模式仍有效”必须区分：控制周期短于无线周期时，不能把某周期没有新帧当成模式退出；须在收到不带标志的新控制帧、STOP或失联时退出。退出处理必须先于旧摇杆分支，不能直接照抄第5.4节的分支顺序。
> - 接管应从主控当前指令姿态执行斜坡；发送端只知道电位器角度，无法保证与机械臂实际姿态一致。现有单轴ARM_POSITION首次使能路径也不能直接当作多轴无跳变跟随实现。
> - 夹爪不参与五路目标映射，但SW7按键仍需可用；第8节“全程夹爪不动”指不按夹爪键的情况。展开收起与目标模式的控制权将在下一步明确。
> - 基座6600计数/圈仍待实测；Kp=8、死区1°、斜率600/s及±165°均是原文建议，未采用或标定。现有基座代码没有完整的编码器断线保护，该保护须随位置环补齐，不能视为已有。
>
> 协议回归：`gcc -std=c11 -Wall -Wextra -Werror -I Modules tools/test_pot_protocol.c Modules/command/command_protocol.c Modules/command/telemetry_protocol.c -o build/test_pot_protocol.exe`，随后运行生成的程序。以上代码路径均相对仓库根目录。

## 1. 一句话结论

芯片 2 现在会在**遥控器已经解锁（ACTIVE）且电位器模式开启**时，把 5 个电位器换算成 5 个关节目标角，
塞进**原有 V3 遥控帧的保留区**（新增标志位 `0x04`）发出去。
主控侧要做的只有三件事：

1. 解出 `Reserved[5..14]` 里的 5 个 `int16`（单位 **0.1°**，小端）；
2. 新增一条"目标角跟随"通道，把它变成舵机 / 基座电机的动作；
3. 遵守第 6 节的安全规则（STOP 优先、失联退出、限位、限速）。

**不做修改时，主控行为与现在完全一致**：帧里多出的位被忽略，机械臂仍走原来的按键/摇杆逻辑。
这一点已经用真实解码器验证过（见第 8 节）。

## 2. 现在的链路

```
芯片1 (F103, 摇杆+按键) --I2C 20B--> 芯片2 (F103, I2C从机 + 5路电位器 + NRF24) --NRF 32B--> F407 主控
```

- 芯片 1：只做输入采集与 I2C 从机写入，不参与任何换算。
- 芯片 2：跑遥控状态机（LOCKED / RESUMING / ACTIVE）+ 读 5 路电位器 + 标定换算 + 组帧 + 无线发送。
- F407：`Modules/command/command_protocol.c` 解码 → `UserApp/components/command/remote_control.c` 解析 → `UserApp/robot/robot.c` 的 `ArmControlStep()` 驱动 `arm.c`。

芯片 2 输出的仍是**同一条 V3 帧**，没有新增版本号、没有新增帧类型、没有占用遥测通道，
所以主控的收包、时序、序号、STOP/RESUME、超时逻辑**全部不需要改**。

## 3. 线上协议

### 3.1 V3 遥控帧（原有，未变）

32 字节，`REMOTE_CONTROL_FRAME_SIZE`：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 1 | 固定 `0xA5` |
| 1 | 1 | 版本 `0x03`（`REMOTE_CONTROL_VERSION_ROBOT`） |
| 2 | 1 | 序号，逐帧递增 |
| 3 | 1 | 标志位，见 3.2 |
| 4 | 8 | M1..M4，`int16` 小端：Vx/Vy/Wz（×1000，m/s、rad/s），M4 = 基座摇杆（×1000，-1..1） |
| 12 | 18 | Reserved[0..17] |
| 30 | 2 | CRC16（多项式 0xA001、初值 0xFFFF，覆盖 0..29） |

原有 Reserved 用法（只在 ACTIVE 帧里有效）：
`[0]` 选中关节 0..3，`[1..2]` 关节速率 `int16` 小端（×1000，-1..1），
`[3]` 展开动作计数器，`[4]` 夹爪动作计数器，`[5..17]` 原本**必须全 0**。

### 3.2 新增标志位

```c
#define REMOTE_CONTROL_FLAG_STOP        0x01U
#define REMOTE_CONTROL_FLAG_RESUME      0x02U
#define REMOTE_CONTROL_FLAG_ARM_TARGETS 0x04U   // 新增：本帧带电位器目标角
```

`0x04` 表示"本帧带有电位器目标角，且操作者已把控制权交给电位器"。

### 3.3 扩展字段（仅在 `flags & 0x04` 时出现）

| Reserved 下标 | 长度 | 内容 | 说明 |
|---|---|---|---|
| 5..6 | 2 | 目标角[0] 基座 | `int16` 小端，单位 **0.1°** |
| 7..8 | 2 | 目标角[1] 肩 | 同上 |
| 9..10 | 2 | 目标角[2] 肘 | 同上 |
| 11..12 | 2 | 目标角[3] 腕俯仰 | 同上 |
| 13..14 | 2 | 目标角[4] 腕旋转 | 同上 |
| 15 | 1 | 标定有效掩码 | 当前恒为 `0x1F`（5 路全部有效），位 i 对应目标角[i] |
| 16 | 1 | 模式字节 | 恒为 `1`，即"目标角模式"；留作以后扩展 |
| 17 | 1 | 保留 | 恒为 `0` |

解码提示（C）：

```c
static int16_t ReadI16(const uint8_t *p) { return (int16_t)((uint16_t)p[0] | ((uint16_t)p[1] << 8)); }
// 0.1° → 度：角度 = ReadI16(Frame.Reserved + 5 + 2 * i) / 10.0f;
```

**为什么是 0.1° 而不是 0.01°**：基座单圈 333°，0.01° 单位的 `int16` 上限只有 327.67°，会溢出；
0.1° 的量程 ±3276.7° 足够，分辨率 0.1° 也远细于舵机实际能做到的精度。

### 3.4 合法性

- CRC 覆盖整帧，扩展字段同样受保护。
- 未带 `0x04` 的 V3 帧，`Reserved[5..17]` 仍按老规则**必须全 0**（解码器照旧拒绝脏数据），
  所以旧的发送方不会被误判，新的解码器也不会放松非目标帧的校验。
- `STOP`（`0x01`）和 `RESUME`（`0x02`）帧**永远不会**带 `0x04`：芯片 2 在组帧后、编码前才附加扩展，
  且附加函数对 STOP/RESUME 直接返回。
- 目标角存在时，`M4`（基座摇杆）与 `Reserved[1..2]`（关节速率）**仍是摇杆值、必须忽略**。

## 4. 什么时候会出现 / 什么时候消失

芯片 2 侧规则（已实现，供理解时序）：

| 事件 | 效果 |
|---|---|
| 遥控 ACTIVE 且电位器稳定 300ms，按 `R_UP + R_DOWN` | 进入目标角模式，目标角从**当前角度**开始（不跳变） |
| 再按一次 `R_UP + R_DOWN`，或按 `R_LEFT + R_RIGHT` | 退出目标角模式 |
| 遥控 LOCKED / 失联 / 输入失效 60ms | 立即退出目标角模式，帧不再带 `0x04` |
| 任意一路电位器超范围或 ADC 失效 | 退出目标角模式 |
| 目标角变化过快 | 每个 20ms 样本最多变化 5°（≈250°/s），主控自身的 90°/s 斜坡仍是最终限速 |

因此主控可以把 `0x04` 的出现/消失当作**明确的模式切换信号**：出现即接管，消失即交还原逻辑。

## 5. 主控侧要改什么

### 5.1 协议层（`Modules/command/`）

`command_protocol.h` 里已经定义了 `REMOTE_CONTROL_FLAG_ARM_TARGETS`，解码器也已放宽保留区校验——
这部分**随本分支一起给到，无需再改**。`RemoteControl_FrameTypeDef` 未变，`Reserved[18]` 原样可读。

### 5.2 解析层（`UserApp/components/command/remote_control.c`）

现有 `RemoteControl_Process()` 在 V3 分支里填 `Arm->Enabled/Joint/Rate/Base/Initialize/Gripper`。
建议在同一个 V3 分支里追加：

```c
typedef struct
{
    uint8_t Valid;            // 本帧带目标角
    uint8_t Mask;             // Reserved[15]
    float   AngleDeg[5];      // 基座,肩,肘,腕俯仰,腕旋转
    uint32_t TickMs;          // 本帧收到的时刻
} RemoteControl_Targets;

static RemoteControl_Targets Targets;   // 放在 RemoteControl_State 里更好，便于加锁

// V3 分支内：
if(Frame.Flags & REMOTE_CONTROL_FLAG_ARM_TARGETS)
{
    for(uint8_t i=0;i<5;i++)
        Targets.AngleDeg[i]=(float)ReadI16(Frame.Reserved+5+2*i)/10.0f;
    Targets.Mask=Frame.Reserved[15];
    Targets.TickMs=NowMs;
    Targets.Valid=(Targets.Mask==0x1F);
}
else Targets.Valid=0;          // 下一帧不带标志即失效，无需超时计时
```

对外加一个取用接口，语义与 `RemoteControl_TakeArmInput()` 一致（取走即清）：

```c
uint8_t RemoteControl_TakeTargets(RemoteControl_Targets *Out);   // 返回 1 表示本次有新的目标角
```

**注意**：`Targets.Valid=0` 要放在 V3 分支的"未带标志"路径上，LOCKED 帧走不到这里也没关系——
LOCKED 帧会让 `Mode` 变成未解锁，下游本来就会停。

### 5.3 执行层（`UserApp/components/arm/`）

现有 API 一次只能下一个关节指令（`Arm_Request(Arm_Command*)`，5 个关节要 5 次），
电位器模式需要**每帧并行下发 5 个目标**，建议在 `arm.c` 里新增一个入口：

```c
void Arm_FollowTargets(const float TargetDeg[5], uint32_t NowMs);
```

内部实现建议（5 个关节现在**全部是位置舵机**，都能直接吃绝对角度）：

| 通道 | 关节 | `Arm_Joint` | 执行器 | 跟随方式 |
|---|---|---|---|---|
| [0] | 基座 | `ARM_BASE`（枚举值 5） | TB6612 + 编码器 | **编码器位置环**（唯一需要新写的控制律）：`PWM = clamp(Kp*(target - BaseRelativeAngleDeg), -300, 300)`，Kp 先取 8（PWM/度），死区 1°，输出斜率限制 600/s |
| [1] | 肩 | `ARM_SHOULDER`（0） | 位置舵机 | 直接作为 `ARM_POSITION` 目标，沿用现有 90°/s 斜坡；角度范围取 `Servos[ARM_SHOULDER].MaxAngleDeg` |
| [2] | 肘 | `ARM_ELBOW`（1） | 位置舵机 | 同上 |
| [3] | 腕俯仰 | `ARM_WRIST_PITCH`（2） | 位置舵机 | 同上 |
| [4] | 腕旋转 | `ARM_WRIST_ROLL`（3） | 位置舵机 | 同上 |
| — | 夹爪 | `ARM_GRIPPER`（4） | 位置舵机 | **不参与**：没有电位器，仍由遥控 `KEY_GRIPPER` 计数触发 |

**枚举顺序容易踩坑**：`Arm_Joint` 的顺序是 `SHOULDER, ELBOW, WRIST_PITCH, WRIST_ROLL, GRIPPER, BASE`，
**不是**舵机序号。电位器通道 0 是基座，对应的是 `ARM_BASE`。

**角度范围不要写死在本文里**：每个舵机的 `MaxAngleDeg`、方向 `Direction` 来自
`ROBOT_ARM_SERVO_CONFIG`（`robot_config.h`），不同批次硬件会变。`Arm_FollowTargets()` 里应当读
`Servos[joint].MaxAngleDeg` 做钳位，而不是用常数。芯片 2 送来的角度是**机械角**，
方向取反、零点偏移都应当由主控这一侧按 `Servos[]` 统一处理。

如果本地代码里某个关节**仍然是** `SERVO_CONTINUOUS`（说明拉取的是旧版本或改动还没合并），
不要为它套用位置目标，按附录 A 的回退方式处理，并把这件事当成"文档落后于实际"报出来。

### 5.4 调度层（`UserApp/robot/robot.c` 的 `ArmControlStep()`）

现有分支顺序建议改为（保持 STOP 最优先）：

```c
if(Stop)                 { Arm_Stop(); ArmRadioOwned=0; ArmTargetOwned=0; }
else if(TakeTargets(&T)) { ArmTargetOwned=1; Arm_FollowTargets(T.AngleDeg, NowMs); }
else if(Input.Enabled)   { ... 原有遥控逻辑 ... }
else if(ArmTargetOwned)  { Arm_Stop(); ArmTargetOwned=0; }   // 目标角停了：停住，不跳回摇杆
else if(Pending)         (void)Arm_Request(&Command, CreatedMs, NowMs);
```

要点：
- 目标角通道**优先于**摇杆通道，否则两边打架；
- 目标角消失时先 `Arm_Stop()` 再回摇杆，避免机械臂突然按摇杆位置跳过去；
- `Stop`（失联 100ms、STOP 锁存）永远第一优先，任何模式下都成立。

## 6. 安全要求（必须全部满足）

1. **STOP 优先**：`RemoteControl_FLAG_STOP`、失联 100ms、`StopGeneration` 变化都必须停，不论是否在目标角模式。
2. **失联退出**：目标角只在收到带 `0x04` 的帧时有效；一帧不带就退出，不做"保持上次目标"。
3. **软限位**：每个关节的上限取本地 `Servos[joint].MaxAngleDeg`（以代码为准，别照抄本文），基座按现场标定的可用行程（建议 ±165°），超限钳位而不是拒绝整帧。
4. **限速**：任何目标跳变都要经过现有斜坡（位置关节 90°/s）或基座输出斜率，不允许阶跃。
5. **上电不许自走**：目标角通道只在遥控 ACTIVE 之后才可能出现，主控侧不要再额外放开这个前提。
6. **夹爪不动**：目标角模式不驱动夹爪，避免和按键计数冲突。
7. **故障即停**：编码器断线、ADC 失效、舵机脉宽越界时按现有 `ARM_HARDWARE_ERROR` 路径停机。

## 7. 标定（芯片 2 侧，无需主控参与）

芯片 2 的默认标定表在 `ArmController/UserApp/arm_targets.c` 的 `DefaultCal[]`，
每路 6 个字段：

```c
{AdcMin, AdcMax, DegMinCdeg, DegMaxCdeg, Dir, SoftMinCdeg, SoftMaxCdeg}
```

| 通道 | 电位器 | 机械 | 默认映射 | 软限位 |
|---|---|---|---|---|
| PA0 | ALPS RDC503013A，10k，333° 单圈 | 基座 | 0..4095 → 0..333°，`Dir=+1` | 5°..328° |
| PA1 | 同上 | 肩 | 0..4095 → 0..333° | 10°..285° |
| PA2 | 同上 | 肘 | 0..4095 → 0..333° | 0°..333° |
| PA3 | 同上 | 腕俯仰 | 0..4095 → 0..333° | 0°..333° |
| PA4 | 同上 | 腕旋转 | 0..4095 → 0..333° | 5°..175° |

> 注意：这张表的软限位是**电位器行程**的边界，不等于舵机能到的角度。
> 真正的舵机限位在主控的 `ROBOT_ARM_SERVO_CONFIG`，两边都要钳，取更严的那个。

改法：只改这张表（`AdcMin/AdcMax` 用实测端点，反向就把 `Dir` 改成 `-1`），重新编译芯片 2 即可，
主控侧无需改动。主控如果想做二次限幅，用同一个表里的软限位数值即可。

## 8. 验收

已完成的（控制器侧，可复现）：

- 两片 F103 全部源文件 `arm-none-eabi-gcc -fsyntax-only` 0 错误 0 警告（用工程真实编译参数）。
- 主机单元测试 17 项全过（`arm_targets.c` + `command_protocol.c` 真实源码）：
  含"0x04 帧能编码、能用真实解码器解出"、"不带 0x04 的脏保留区仍被拒"、"锁定时不能进入目标角模式"、
  "失效/失控输入立即退出"、"每帧限幅 5°"。
- 因此主控**现状**（不实现目标角）也不会被新帧破坏：多余的标志位与保留区被忽略。

主控侧完成的判定（台架，先断动力或架空机械臂）：

1. 芯片 2 串口每秒一行的统计里 `POT=1` 时，遥控按下 `R_UP+R_DOWN` → 主控 `Arm_Status` 进入目标角跟随。
2. 逐个转动 PA1..PA4（肩/肘/腕俯仰/腕旋转），对应关节的 `CommandedAngleDeg` 在 1s 内跟到 ±3° 以内。
3. 转动 PA0（基座），基座编码器角度跟随，超行程时钳位不越界。
4. 把每路电位器推到两端，关节都应停在 `Servos[joint].MaxAngleDeg` 之内，不撞机械限位。
5. 松开摇杆、断开芯片 2 电源 → 100ms 内停机，机械臂不保持运动。
6. 遥控锁定 → 立即停机；再解锁后不自动恢复目标角，必须重新按 `R_UP+R_DOWN`。
7. 全程夹爪不动。

- 基座电位器 333° 单圈，超过一圈无法表示；若现场需要多圈，得换多圈电位器或改用编码器计数。
- 夹爪没有电位器，目标角模式不控制夹爪。
- 线上精度 0.1°，且每 20ms 最多 5°；不足以做快速轨迹，但足够手动跟随。
- 基座是唯一没有位置舵机的关节，位置环要靠编码器自己写，`Kp` 与输出斜率必须上台架整定。

## 附录 A：如果某关节仍是连续舵机（回退方案）

只有当本地代码里该关节的 `Servos[joint].Mode == SERVO_CONTINUOUS` 时才用这一节：

- 不能下发绝对角度，改为速率跟随：主控自己维护估算角 `est += Rate*dt`，
  `Rate = clamp(Kp*(target - est), -1, 1)`，`Kp` 先取 0.05（每度）。
- 进入目标角模式的第一帧把 `est` 对齐到目标，避免起步猛冲。
- `est` 是开环积分，会漂，只能当诊断量，不要写进任何"实测角度"字段。
- 一旦硬件换成位置舵机，就删掉这条路径，不要两套并存。
