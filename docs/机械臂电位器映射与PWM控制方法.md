# 机械臂电位器映射与 PWM 控制方法

面向读者：需要在主控侧把"自定义控制器的五路电位器"变成"机械臂动作"的人（HJC）。
本文给出一条从 **ADC 计数** 到 **舵机脉宽 / 底座 PWM** 的完整换算链，并附上 2026-10-25 在实物控制器上拟合出的参数。
主控侧的帧格式与接入位置见《主控侧机械臂目标角接入说明.md》，本文只讲**换算与控制**。

> **优先关系**：若本文与本地代码冲突，一律以代码为准
> （`UserApp/robot/robot_config.h` 的 `ROBOT_ARM_SERVO_CONFIG`、`UserApp/components/arm/*`、`Modules/actuator/servo.c`）。
> 本文的换算公式就是按这些文件的实际实现写的。

---

## 1. 一句话结论

五路电位器的映射可以拆成**五级串联换算**，每一级都是"线性 + 钳位"，没有查表和拟合：

```
ADC 计数 ─①归一化→ r∈[0,1] ─②标定→ 关节角 θ ─③限幅限速→ θ* ─④执行器换算→ 脉宽/PWM ─⑤下发
```

只要把第 2 级的三个参数（方向、量程、零点）按实物标定好，这条链就能直接驱动机械臂，不需要额外算法。

---

## 2. 编号对照（先看这个，容易错）

工程里有**两套编号**，混用会导致关节错位：

| 视图/电位器侧 | ADC 引脚 | `Arm_Joint` 枚举 | 说明 |
|---|---|---|---|
| J1 BASE | PA0 | `ARM_BASE`（=5） | 直流电机 + 编码器，不是舵机 |
| J2 SHOULDER | PA1 | `ARM_SHOULDER`（=0） | 位置舵机 |
| J3 ELBOW | PA2 | `ARM_ELBOW`（=1） | 位置舵机 |
| J4 WRISTP | PA3 | `ARM_WRIST_PITCH`（=2） | 位置舵机 |
| J5 WRISTR | PA4 | `ARM_WRIST_ROLL`（=3） | 位置舵机 |
| —（无电位器） | — | `ARM_GRIPPER`（=4） | 按键开合，两档 |

注意 `arm_def.h:5` 的枚举顺序是 **肩、肘、腕俯仰、腕旋转、夹爪、底座**，底座排在最后；
而电位器通道顺序是 **底座、肩、肘、腕俯仰、腕旋转**（`arm_targets.c` 的 `Cal[]` 顺序）。
帧里 `Reserved[5..14]` 的五个 `int16` 用的也是**电位器顺序**，主控解出来要按上表重排。

## 3. 五级换算

### ① 归一化（含端点与方向）

```
r = (ADC - AdcMin) / (AdcMax - AdcMin)       # 结果钳位到 [0,1]
若 Dir < 0:  r = 1 - r
```

- `AdcMin/AdcMax` 必须是**机械行程两端实测的计数**，不能写 0/4095。旋钮到端点时电位器会打满并在 4095↔0 之间跳变，端点要各留余量；按现有实测，建议先取 `200 / 3900`。
- `Dir` 只表示"ADC 增大时关节角往哪边走"，与 `arm_targets.c` 里的 `Dir` 同义。

### ② 标定成关节角

```
θ = θ_min + r * (θ_max - θ_min)        [度]
```

等价写法（与可视化工具的 `sign/span/zero` 一一对应）：

```
θ = Sign * (Zero + Span * r)
    Zero = θ_min  （r=0 时的关节角）
    Span = θ_max - θ_min （电位器走完全行程对应的关节角变化）
    Sign = Dir
```

`Span` 就是"主从比例"：主手行程 333°，若关节只走 150°，则 `|Span| = 150`，操作会变精细；若 `|Span| > 舵机行程`，第 ④ 级会因超出 `MaxAngleDeg` 被拒绝（`servo.c:13` 返回 0），必须压缩或用增量式（见 6.3）。

### ③ 软限位与限速

```
θ* = clamp(θ, SoftMin, SoftMax)
|θ*(k) - θ*(k-1)| <= RateMax * Δt
```

芯片 2 当前的限速是 `ARM_TARGET_MAX_STEP_CDEG = 500`（5°/20 ms = 250°/s），软限位在 `arm_targets.c` 的 `DefaultCal` 里逐路给出。

### ④ 位置舵机 → 脉宽

`Modules/actuator/servo.c:11-17` 的实际实现：

```
ratio = θ_servo / MaxAngleDeg
若 Direction < 0:  ratio = 1 - ratio
pulse_us = UsMin + ratio * (UsMax - UsMin)      # 500 .. 2500
```

肩关节有固定机械零点（`robot_config.h:71`）：

```
θ_servo = ROBOT_ARM_SHOULDER_ZERO_DEG(150) + θ_shoulder      # θ_shoulder ∈ [0,150]
```

### ⑤ 底座直流电机 → PWM

底座不能用脉宽（`arm.c:256`）：

```
θ_encoder = counts * 360 / ROBOT_ARM_BASE_CPR(6600)          # 18.33 计数/度
e = θ* - θ_encoder
BasePWM = clamp(Kp*e + Ki*∫e, -1, 1) * ROBOT_ARM_BASE_PWM_LIMIT(300)
```

- `STBY` 只在 `BasePWM != 0` 时拉高；
- 编码器是**相对**的，上电位置即零点，所以底座目标角必须先减上电时的 `θ_encoder`；
- 实测：归一化量 0.25 / 0.5 / 0.75 / 1.0 对应 1.5 / 3.7 / 6.2 / 9.0 rpm，可作前馈项。

## 4. 实测参数（2026-10-25）

在实物控制器上，用 `tools/ArmViewer.ps1` 调 `1-5` 选关节、方向键调零点与量程、`S` 翻极性，
把画面姿态调到与实机一致后取下的值：

| 视图关节 | span | zero | sign | r=0 时关节角 | r=1 时关节角 |
|---|---|---|---|---|---|
| J1 BASE | 340 | -170 | -1 | **+170°** | **-170°** |
| J2 SHOULDER | 335 | 193 | -1 | **-193°** | **-528°** |
| J3 ELBOW | 315 | -163 | +1 | **-163°** | **+152°** |
| J4 WRISTP | 300 | -155 | -1 | **+155°** | **-145°** |
| J5 WRISTR | 360 | -180 | +1 | -180° | +180°（未实测，沿用默认） |

ADC 端点暂取 `200 / 3900`（五路相同），尚未按各自的实际机械端点单独测。

**这组数的性质**：是为了"画面与实机姿态一致"拟合出来的角度，**不是**伺服标定表。
它已经可以直接用来驱动，但要落到舵机上必须做两件事：

1. **归一化到舵机行程内**。这些角有 360° 周期等价，例如肩 `-528°` 等价于 `+192°`；舵机只能 0..`MaxAngleDeg`，所以要先加整数个 360° 取最接近的等价角，再钳位。
2. **核对行程是否超限**。J2 拟合行程 335°、J3 为 315°，都超过多数舵机的 300°／270° 行程。若实测机构确实到不了这么宽，应把 `Span` 压到舵机能覆盖的区间，或在机构上改减速比。

> 采集状态说明：取这组数时串口已停（界面显示 `STALE`，五路 ADC 读到 0），数值是最后一次调定的结果。
> 接回电位器供电后建议用 `-Shot`／`-Replay` 复验一次再写进固件。

## 5. 换算成固件参数表

`ArmController/UserApp/arm_targets.c` 的 `ArmTarget_Cal` 字段顺序是：

```c
{ AdcMin, AdcMax, DegMinCdeg, DegMaxCdeg, Dir, SoftMinCdeg, SoftMaxCdeg }
```

单位是 **0.01°（cdeg）**；上遥控帧时再 `/10` 变成 0.1°。

`MapAngle()` 里 `Dir<0` 的实现是"把分子取反"，所以 **`Dir<0` 时 ADC 最小对应 `DegMax`**。换算规则：

```
Sign = +1:  DegMin = Zero        , DegMax = Zero + Span
Sign = -1:  DegMin = -(Zero+Span), DegMax = -Zero
```

按第 4 节的实测值换算：

| 通道 | AdcMin/Max | DegMin (cdeg) | DegMax (cdeg) | Dir |
|---|---|---|---|---|
| 底座 | 200/3900 | -17000 | +17000 | -1 |
| 肩 | 200/3900 | -52800 | -19300 | -1 |
| 肘 | 200/3900 | -16300 | +15200 | +1 |
| 腕俯仰 | 200/3900 | -14500 | +15500 | -1 |
| 腕旋转 | 200/3900 | -18000 | +18000 | +1 |

直接替换 `DefaultCal[]` 时保持数组顺序为 **底座、肩、肘、腕俯仰、腕旋转**，软限位先按舵机可达范围填，等机械装配完成再收紧。

## 6. 执行器一侧的硬约束

### 6.1 舵机配置

`robot_config.h:63-68` 当前是：

| 关节 | 模式 | UsMin | Neutral | UsMax | MaxAngleDeg | Dir |
|---|---|---|---|---|---|---|
| 肩 | POSITION | 500 | 1500 | 2500 | 300 | -1 |
| 肘 | **CONTINUOUS** | 500 | 1500 | 2500 | 0 | -1 |
| 腕俯仰 | **CONTINUOUS** | 500 | 1500 | 2500 | 0 | +1 |
| 腕旋转 | POSITION | 500 | 1500 | 2500 | 180 | +1 |
| 夹爪 | POSITION | 500 | 1500 | 2500 | 180 | +1 |

**已知不一致**：实机 5 个关节已全部换成位置舵机，但表里肘和腕俯仰还是 `CONTINUOUS`。
按这两行配置，④ 级会走"速率"分支（输入是 -1..1 的归一化量），角度根本到不了。
必须改成：

```c
{ SERVO_POSITION, 500, 1500, 2500, <实测行程>, <方向> },
```

`MaxAngleDeg` 填舵机铭牌行程（常见 180/270/300），`Direction` 填 +1/-1。

### 6.2 计算示例

肩关节目标 90°：

```
θ_servo = 150 + 90 = 240
ratio   = 240 / 300 = 0.8
Dir = -1 → ratio = 0.2
pulse   = 500 + 0.2 * 2000 = 900 µs
```

### 6.3 行程不够时的增量式

若某关节行程大于舵机行程，只能用增量映射：

```
θ*(k) = clamp(θ*(k-1) + K * (r(k) - r(k-1)), SoftMin, SoftMax)
```

代价是漂移，必须提供复位键（控制器上已有 `R_LEFT+R_RIGHT` 退出 POT 模式的孔位组合，可复用）。

## 7. 标定流程（两点法）

每路 5 分钟，需要两个人：

1. 把关节手推到**一端机械极限**，记录 ADC 与关节角 → 得到 `(AdcA, θA)`；
2. 推到**另一端**，记录 → `(AdcB, θB)`；
3. 打开 `tools/ArmViewer.ps1`，按 `1-5` 选中该关节，用方向键/`S` 调整到两端都与实机一致，按 `W` 存盘；
4. 把 `ArmViewer.tune.txt` 里该行按第 5 节换算成 `DegMinCdeg/DegMaxCdeg/Dir`；
5. ADC 端点取两端实测值各向内收 3%，避免打到饱和区跳变；
6. 软限位取机械极限再各留 5°。

## 8. 安全与失效

这几条比公式重要，全部要在主控侧实现：

| 场景 | 处理 |
|---|---|
| 100 ms 收不到有效帧 | 清目标、输出归零，机械臂保持最后位置 |
| STOP 帧 | 锁存，必须显式 RESUME，且四个速度先归零 |
| 某通道 ADC 读到 0 或超出 `[AdcMin, AdcMax]` | 该关节**保持不动**，不要当 0° 处理 |
| 上电 | 底座以当前位置为零点；舵机先回 `PRESET` 再进入跟随 |
| 目标角超软限位 | 钳位，不报错 |
| 舵机脉宽超 `[UsMin, UsMax]` | `Servo_Pulse()` 返回 0，该路输出 0（不是钳位）→ 上层必须保证不越界 |

## 9. 验收判据

1. **单关节慢扫**：全程慢速推拉，实机角度与 `θ*` 偏差 ≤ 3°，无跳变、无反向；
2. **端点**：推到两端，输出停在软限位上，不同步、不越界；
3. **失联**：拔掉 2.4G 或关主控，100 ms 内机械臂停止；
4. **重上电**：姿态不变、底座不甩；
5. **全姿态回放**：用 `-Replay` 回放一段录制日志，画面与实机动作逐帧对得上。
