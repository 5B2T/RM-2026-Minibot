# 双芯片控制器接线与测试

2026-10-22机械臂更新：J2换JX6225 300°、J3换MG90D 270°，五路均为位置舵机；旧机械零位/限位/展开目标作废，SW6按新姿态大臂先行、其余三轴并行展开/J3→J2→J4→J1顺序收起，新机械限位已配置，SW7恢复0°闭合/30°张开。无线V3、两块F103及接线不变；F407已烧录并三段校验、待机读回通过，未启动运动。串口上位机改ARMDBG V2、25通道，见工作区《机械臂串口协议.md》，实物联调待验证。

## 固件与构建

- 芯片1：RemoteController，STM32F103C8T6，内部 HSI + PLL 64 MHz。
- 芯片2：ArmController，STM32F103C8T6，内部 HSI + PLL 64 MHz。
- 分别进入对应工程目录，执行 `cmake --preset Debug`、`cmake --build --preset Debug`。
- 输出为各工程 `build/Debug` 中的同名 `.hex`、`.bin`、`.elf`。
- 芯片1不构建OLED和无线业务，OLED实现已删除；不初始化SPI2。芯片2复用最新遥控业务和V3整车控制协议。
- 芯片1仍输出按键串口消息，没有 JOY 定时输出。芯片1的 USART1 由原 test.c 初始化。
- CubeMX 的 .ioc 不是新增板级初始化的完整来源。芯片2新增外设由 Bsp/arm_board.c 配置，不要只重新生成 .ioc 就删除这些调用。芯片1的PA5/PA7标签已改为INPUT_LINK_SCL/SDA；两板目前均由源码配置内部HSI+PLL时钟，重新生成时需核对时钟与外设初始化。
- 两板串口诊断均采用非阻塞发送队列，日志拥塞丢弃诊断字节，不阻塞控制循环。

## 接线

| 信号 | 芯片1 | 芯片2 |
| --- | --- | --- |
| SCL | PA5，软件开漏输出 | PB6，硬件 I2C1 从机 |
| SDA | PA7，软件开漏输出 | PB7，硬件 I2C1 从机 |
| GND | GND | GND |

断开芯片1原 OLED。短线测试时 SCL、SDA 各用约 4.7 kΩ 上拉到 3.3 V；如已有上拉先核对等效阻值。两板共地，不需要把两个独立稳压器的输出直接并联。

芯片2五个电位器滑动端：J1 PA0、J2 PA1、J3 PA2、J4 PA3、J5 PA4；分压两端为 3.3 V/GND。ADC 采用较长采样时间，五通道每约 20 ms 采样。

芯片2 NRF24L01：CE PB12、CSN PB10、SCK PB13、MISO PB14、MOSI PB15、IRQ PB11，SPI2。按模块规格接 3.3 V 及去耦。当前使用轮询，不依赖 IRQ 中断。

两个芯片串口均为 PA9 TX、PA10 RX、115200 8N1。TX 接 USB 串口 RX，并共地。调试器 SWDIO 接 PA13，SWCLK 接 PA14，建议另接 NRST 和目标参考电压。

## 芯片间输入协议

主机每 20 ms 写七位地址 0x32（写地址字节 0x64），固定 20 字节，小端格式：

| 字节 | 含义 |
| --- | --- |
| 0 | 0xA6 |
| 1 | 版本 1 |
| 2 | 递增序号，模 256 |
| 3 | ADC 输入有效，0 或 1 |
| 4～5 | 按键位图，沿用 Remote_Key |
| 6～15 | 五个 uint16 ADC：芯片1 PA1、PA2、PA3、PA6、PA4 |
| 16～17 | 保留，发送 0 |
| 18～19 | 前 18 字节 CRC16 Modbus，初值 FFFF，多项式 A001 |

芯片1发送原始按键状态，芯片2使用Controller_Update做去抖、关节选择和全车使能逻辑。左上PA11使能、左下PA12停止并锁定；左摇杆PA1减小前进、PA2减小左移（2026-10-29实测修正，中继已更新、整车待复核）。SW6触发大臂先行、后三轴并行、末尾夹爪张开；收起首步J3与夹爪同步，SW7切换夹爪0°闭合/30°张开；摇杆按压不采集，SW5为硬件复位。当前操作见遥控器操作说明。

输入序号重复或过旧不刷新状态；100ms后允许重新同步序号。沿用10月21日master修改：60ms未更新即输入失效，底盘/底座/关节速率清零，保持原模式；连续无效200ms才锁定。短暂失效恢复可继续ACTIVE控制；一旦已锁定，必须两摇杆回中、松开按键后重新按左上PA11，持续按住不能自动解锁。使能恢复阶段输入失效立即锁定。CRC、保留字节、按键位图及ADC范围异常的帧不刷新输入期限。

芯片2接收中断只复制固定帧，主循环做 CRC、值域和新旧序号检查。软件主机支持时钟拉伸，整次事务约 10 ms 超时，支持九脉冲总线恢复；从机异常和未完成事务在主循环重建监听。

## 芯片2无线

芯片2复用遥控控制器和射频模块，每20ms发送32字节整车V3帧；默认锁定发送STOP，零输入RESUME后才允许控制底盘、底座和选中关节。单次动作计数器接口保留，SW6使用本次五轴分组展开/收起，SW7使用新0/30°端点。协议定义位于Modules/command/command_protocol.h。

**远端原电位器遥测同样使用A5/03，与整车V3控制帧冲突，已删除无线发送入口及遥测组帧函数。**五路电位器继续采样，仅在芯片2串口输出原始POTS，不换算未标定角度，不影响按键和摇杆控制，也不占用无线控制时隙。未来若增加遥测或仿真臂跟随，需要独立帧类型、标定和车端接收实现。

## 台架测试顺序

1. 先断开底盘和机械臂动力电源，只接控制器和无线低压电源。
2. 给芯片1烧 RemoteController.hex，给芯片2烧 ArmController.hex。两颗型号相同，换 SWD 线时必须明确板号，不能只凭芯片 ID 判定。
3. 芯片1启动串口应显示 CHIP1 INPUT BRIDGE。绿色 PB4 按原硬件低电平有效设计，表示最近一次 I2C 事务获得 ACK；不证明芯片2已通过 CRC 或主控执行。
4. 芯片2串口每秒输出I2C RX、ERR、VALID、KEYS、ACK、MODE、J、LOCK、N、五路POTS、ADC。RX计数应持续增长，VALID应为1。ACK是整车无线命令应答，MODE=0/1/2分别为锁定/恢复中/允许控制，J=1～4为选中关节。LOCK记录最近失能首因，N为失能次数，含义见遥控器操作说明；这些均不是执行器到位反馈。
5. 逐个按键并拨动摇杆。芯片1仍有 KEY DOWN/UP 消息；芯片2 KEYS 应变化。断开 I2C 应使 VALID 清零、状态锁定。
6. 五路电位器逐个转动，芯片2对应 POTS 应在 0～4095 内变化。悬空 ADC 值不代表传感器真实有效，ADC=1 只代表转换成功。
7. F407 接收端上电后，芯片2 ACK 应为 1；先保持锁定检查主控 LINK ONLINE、ARMED NO。不要为了看遥测直接解锁带动力的底盘。
